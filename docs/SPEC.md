# AromaShooter UDP Bridge 仕様書

版：1.0 / 作成日：2026-10-06

本書は実装の正本となる仕様。2026-10-07に初版を実装し、Windows Releaseビルドと模擬SDKによる自動テストを実施した。USB/BLE実機試験は未実施。検証範囲はdocs/VERIFICATION.mdを参照。

## 1. 目的と範囲

Windows上でトレイ常駐し、UDPで受け取った噴射・停止指示を公式Windows SDKへ中継する。
噴射のタイミング、タイムライン、シーケンス、キュー管理は外部制御側が担当する。
本アプリは時刻予約、シーケンス再生、AromaPlayerの.nfc読み書きを実装しない。

## 2. 技術構成

- アプリ名・実行ファイル名：AromaShooterUdpBridge / AromaShooterUdpBridge.exe。
- Windows 10 / 11、C#、WinForms、.NET Framework 4.7.2、Visual Studio 2022。
- NotifyIconによるトレイ常駐。Windowsサービスではない。
- JSON：Newtonsoft.Json。ビルド時に解決した依存DLLも配布する。
- 公式SDK：AromaShooterWindowsSDK.dll、SDK文書Version 3.0.0。
- SDK入手元：<https://github.com/aromajoin/aromashooter-sdk-windows>
- DLLをlib/net472/に配置し、プロジェクト参照から出力へコピーする。
- USBはシリアル/COM接続。BLEはBluetooth LE接続。設定で一方を選ぶ。
- 公式SDKの実装ソースは配布DLLから独立して公開されているとは限らない。文書とサンプルでAPIを確認し、未確認の振る舞いを作り話で補わない。

## 3. 起動・接続・終了

1. ユーザー単位のMutexで単一起動とする。二重起動時は既存の設定ウィンドウを表示して新プロセスを終了する。
2. 設定を読み込み、UDP待受を開始する。初回は既定の設定ファイルを生成する。
3. 起動時に設定の`showWindowOnStartup`がtrueなら設定画面を表示し、falseならトレイのみで起動する。既定はtrue。設定エラー時は設定画面を表示する。設定画面を閉じてもアプリは終了しない。
4. `autoConnect`がtrueなら選択した接続方式で非同期に検出・接続する。設定画面を表示する起動では画面を先に表示し、接続完了を待たず操作可能にする。
5. 初回または設定・待受エラー時は設定画面を表示する。
6. 接続失敗時もUDP待受とUIは維持し、再接続ボタンで再試行できる。
7. 接続機器が0台の間は5秒ごとに検出・接続を再試行し、1台以上を検出したら自動スキャンを止める。`autoConnect`がfalseなら起動時接続と定期スキャンを行わない。定期スキャンは制御ワーカーで直列化し、重複実行しない。未検出の周期ごとにはログを出さず、検出成功またはエラーを記録する。切断中の噴射指示は保留せず破棄する。手動再接続時は指示受付を一時停止し、キュー破棄・全停止・切断後に検出を行う。
8. 終了時はUDP受信停止、未実行指示破棄、全停止、DisconnectAll、NotifyIcon破棄の順で処理する。停止や切断で例外が出ても残りの終了処理を続ける。

## 4. UDPプロトコル

### 4.1 共通形式

- 独自のプレーンテキストUDP。OSCではない。
- UTF-8、1データグラムにつき1コマンド、最大1024バイト。
- 前後の空白と末尾のCR/LFは除去する。内部の改行、複数コマンド、BOM、不正UTF-8は拒否する。
- 引数区切りは1個以上の半角スペース。カンマの前後に空白は入れない。
- コマンドとALLは大文字・小文字を区別しない。機器シリアル番号は大文字・小文字を含め完全一致。
- 数値は10進の整数。小数、負数、数値文字列以外の表現は拒否する。
- 応答・ACK・再送・配送保証・重複排除は初版では実装しない。
- UDP受信時刻が噴射の開始指示のタイミングとなる。厳密な開始時刻や実機開始の確認は保証しない。

### 4.2 噴射

```text
SHOOT <target> <chambers> <durationMs> [intensities]
```

| 引数        | 意味・制約                                                                             |
| ----------- | -------------------------------------------------------------------------------------- |
| target      | ALL、またはGetConnectedDevices()で取得したシリアル番号                                 |
| chambers    | 1〜6のカンマ区切り。1個以上、重複不可                                                  |
| durationMs  | 噴射長。ミリ秒。1〜2147483647の整数。必須                                              |
| intensities | 0〜100の整数をカンマ区切り。chambersと同じ個数・同じ順序。省略時は各チャンバーの設定値 |

例：

```text
SHOOT ALL 1 3000
SHOOT ALL 1,3 3000
SHOOT ALL 1,3 3000 50,80
SHOOT ASN3A01192 2 1500 70
```

- 指定チャンバーのみ噴射する。指定されていないチャンバーへ既定強度を送らない。
- durationMsは噴射時刻ではなく噴射長。アプリのタイマーで遅延開始しない。
- 強度0も有効。内部ブースター強度は設定の1〜100、外部ブースター強度は設定の0〜100を使用する。
- 設定値は噴射時の既定値であり、起動・設定変更だけでは噴射しない。

### 4.3 停止

```text
STOP ALL
STOP ASN3A01192
```

停止対象の全チャンバーとブースターを停止する。チャンバー単位の停止は初版のUDP仕様に含めない。

### 4.4 対象と再噴射

- ALLはコマンド実行時点で接続中の全機器。後から接続された機器への遡及実行はしない。
- 未接続・不明シリアルはログに記録して破棄する。勝手にALLへ置換しない。
- 同一機器への新しいSHOOTは既存噴射を置き換える。対象機器の全停止を呼んでから新しい噴射を呼ぶ。
- 複数チャンバーの同時噴射は1つのSHOOTで指定する。別SHOOTで累積・重ね合わせはしない。
- 他の機器の噴射は停止しない。
- パケット重複も新しいSHOOTとして扱うため噴射が再開始する。送信側はSHOOTを無条件に再送しない。
- SDK呼び出しとUIのテスト操作は共通の直列実行経路にする。通信の到着順・時刻同期はUDPの保証範囲外。
- 有効なSTOPは未実行の対象SHOOTを取り消し、進行中のSDK呼び出し終了後に優先実行する。ALLは全対象に適用する。
- 待ち行列は最大100件。超過したSHOOTは破棄して記録する。STOPは満杯でも受け付ける。
- 検証に失敗したコマンドは、既存噴射を止めるなどの副作用を起こさない。

## 5. 設定ファイル

保存先：%LOCALAPPDATA%\AromaShooterUdpBridge\settings.json。
初版はこの固定パスのみとし、exe付近との二重管理をしない。

```json
{
  "schemaVersion": 2,
  "udp": {
    "listenAddress": "0.0.0.0",
    "port": 10000
  },
  "device": {
    "transport": "USB",
    "autoConnect": true,
    "showWindowOnStartup": true
  },
  "shoot": {
    "defaultIntensities": [100, 100, 100, 100, 100, 100],
    "internalBoosterIntensity": 100,
    "externalBoosterIntensity": 0
  }
}
```

- udp.port：1〜65535。listenAddress：IPv4のローカル待受アドレス。0.0.0.0で全IPv4インターフェース、127.0.0.1で同一PCのみ。
- device.transport：USBまたはBLE。接続方式の同時使用は初版では行わない。
- defaultIntensities：必ず6個、配列の先頭からチャンバー1〜6、各0〜100。
- internalBoosterIntensity：1〜100。香り噴射に内部ブースターが必要なため0は禁止。
- externalBoosterIntensity：0〜100、既定0。
- schemaVersion：2を保存する。旧schemaVersion 1も読み込み可能とし、`showWindowOnStartup`をtrueとして扱う。その他の未知プロパティ・未対応版・型違い・不足項目・範囲外は設定エラーとする。
- device.showWindowOnStartup：起動時に設定画面を表示するか。trueが既定。自動復旧などの画面非表示起動ではfalseを指定する。
- 初回のファイル不存在に限り既定値を生成する。既存ファイルの破損時は上書きせず、UDP待受と自動接続を開始しない。UIから修正または明示的に既定値へ戻せる。
- UI変更は同じJSONへ保存する。外部編集は［設定を再読み込み］で反映し、ファイル監視はしない。
- 書き込みは同じディレクトリの一時ファイルからの置換で行い、保存失敗を表示する。
- 設定を変更しても実行中の噴射へ強度変更を追送しない。次のSHOOTから新設定を使用する。
- ポート変更時は新待受を確保してから切り替える。失敗時は旧待受・旧設定を維持する。同一エンドポイントなら再バインドしない。同じポートで待受アドレスだけを変えるなど旧待受との重複が避けられない場合は、旧待受を閉じて変更を試み、失敗したら旧待受を再開する。
- 保存・適用失敗時は前の正常設定と待受へ戻す。元の状態へ戻せなかった場合は待受停止を明示する。
- 接続方式の変更時は指示受付を一時停止し、キューを破棄、旧機器を停止・切断してから切り替える。接続失敗は表示し、旧方式へ暗黙に戻さない。
- UI編集中にファイルが外部変更された場合は上書き前に検出し、再読み込みまたは明示的な上書きを選択させる。

## 6. UIとログ

トレイダブルクリックで設定画面。メニューは［設定・状態］［全停止］［再接続］［終了］。［全停止］は接続機器の全チャンバーとブースターを停止し、待機中の対象SHOOTを取り消す。SDKの噴射呼び出し中は中断できず、呼び出し完了後に停止する。［設定フォルダーを開く］は設定ウィンドウ左下のテキストリンク、［設定を再読み込み］は右下のボタンから操作する。

設定画面には以下を配置する。

ライト基調のUIとし、チャンバー既定強度・内部/外部ブースターは［詳細設定］、テスト操作は［テスト］へ収納する。両領域は初期状態で折りたたみ、見出しクリックで開閉する。再接続は右上のアイコン（ツールチップ付き）とし、ボタン中央に描画して上下左右の余白をそろえる。［設定を再読み込み］［リセット］［適用して保存］は下部右寄せとし、［適用して保存］のみ大きく強調する。展開時は中央領域をスクロールでき、下部操作は固定する。リセットは確認後に既定値を保存・適用する。

- 待受アドレス・UDPポート、USB/BLE、起動時自動接続、起動時の設定画面表示。
- チャンバー1〜6の既定強度、内部・外部ブースター強度。
- ［適用して保存］［設定を再読み込み］。
- UDP待受状態、接続方式、検出済みシリアル一覧、最終エラー。
- テスト操作：対象機器/ALL、複数チャンバー、噴射長、既定強度を使う噴射ボタン、全停止。
- テスト噴射長のUI初期表示は3000ms。UDPの噴射長には既定値を使わない。
- 受信・実行ログ：時刻、送信元IP/ポート、コマンド、対象、SDK呼び出し結果、エラー。

SDKが完了通知を返さない場合、成功表示は［SDK呼び出し完了］とする。［実機噴射確認済み］とは表示しない。
接続一覧は最後の検出結果であり、常時の実機生存確認とは扱わない。`autoConnect`が有効で検出機器が0台の場合だけ5秒ごとに再検出する。
ログはUIで直近500件、ファイルで日別UTF-8ログを7日分保持。保存先は設定フォルダー内のlogs/。
ログ保存失敗がUDPや停止を止めないようにする。UI更新とスキャンをUIスレッドで長時間ブロックしない。

## 7. SDKマッピング

| 処理             | USB                                                                                                        | BLE                    |
| ---------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------- |
| 接続             | ScanAndConnect()                                                                                           | await ScanAndConnect() |
| 一覧             | GetConnectedDevices()                                                                                      | GetConnectedDevices()  |
| 噴射             | ShootWithIntensity(durationMs, chambers, internalBoosterIntensity, externalBoosterIntensity, deviceSerial) | 同名API                |
| 全チャンバー停止 | StopWithIntensity(deviceSerial, new[] {1,2,3,4,5,6}, true, true)                                           | 同名API                |
| 切断             | DisconnectAll()                                                                                            | DisconnectAll()        |

コントローラーはAromaShooterControllerUSB.SharedInstanceまたはAromaShooterControllerBLE.SharedInstance。
chambersはList<AromaChamber>、numberが1〜6、concentrationが0〜100。
ALLは接続一覧を取得して機器ごとに呼び出す。1台の失敗で他の機器への処理を中断しない。
実装時は配布DLLの実際のシグネチャとサンプルで照合する。メソッドの戻り値、例外、呼び出し所要時間、最大噴射長、切断検出は未確認。

2026-10-07のDLL照合結果：USBのScanAndConnect、両方式のShootWithIntensity、StopWithIntensity、DisconnectAllはvoid。BLEのScanAndConnectはTask<List<string>>、GetConnectedDevicesは両方式ともList<string>。例外の実機発生条件、所要時間、最大噴射長、切断検出の保証は引き続き未確認。停止呼び出しで例外が出た機器には続く噴射を送らず、他機器の処理は継続する。
噴射長の入力上限は整数APIへの受け渡し上限であり、実機がその全範囲を保証するという意味ではない。SDK・実機に別制限が判明したら仕様・検証・READMEを同時に修正する。

## 8. エラー処理

- 不正UDPは理由と送信元を記録して破棄。プロセスを終了しない。
- バインド失敗は実アドレス・ポート・理由を表示。黙って別ポートで起動しない。
- SDK例外は対象機器ごとに記録する。停止失敗はUIに残す。
- 接続中・切替中・未接続時のSHOOTは破棄し、後から実行しない。
- 終了中のSHOOTは受け付けない。
- ファイアウォール設定はアプリから自動変更しない。別PCから使用する場合の受信許可手順をREADMEへ記載する。

## 9. 受入条件

### 実機なしで必須

- WindowsでReleaseビルドが成功し、SDK・依存DLLが出力される。
- 正常/不正UDPの解析、範囲、引数個数、未知対象、UTF-8を検証する。
- 省略強度が各チャンバーの設定値、指定強度が今回のみの値になることを検証する。
- SDKを差し替えたテストで、対象機器のみ停止→噴射、他機器への非干渉、STOP優先、キュー上限、切断中の破棄を確認する。
- ポート変更成功・競合失敗時の旧待受維持、外部編集の再読み込み、破損JSONの保全を確認する。
- 二重起動、設定画面を閉じた後の常駐、トレイ終了時の後始末を確認する。

### 実機がある場合

- USB、BLEは利用可能な方式ごとに検証し、未検証方式を明記する。
- 3000ms噴射、自動停止、途中STOP、複数チャンバー、強度変更、再噴射による置換を確認する。
- 複数台へのALL、個別制御、抜線、再接続、終了時停止を確認する。
- 公式AromaPlayerとのUSB占有競合を確認する。USB/COMは同時に1アプリのみ。
- UDP・SDK・実機で検証できた範囲を分けて報告する。
