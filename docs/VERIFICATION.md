# 検証記録

実施日：2026-10-07。Windows、.NET SDK 8.0.301、.NET Framework 4.7.2を対象に実施。

## ビルドと依存物

- `dotnet build .\AromaShooterUdpBridge.sln -c Release`：成功、警告0、エラー0。
- 公式AromaShooterWindowsSDK.dllをSDK配布フォルダーから無改変でコピー。
- DLLの公開APIをReflectionで読み、公式READMEとSmokeTestに照合。
- USB ScanAndConnect：void、BLE ScanAndConnect：Task<List<string>>。
- 両方式ともGetConnectedDevices：List<string>、ShootWithIntensity / StopWithIntensity / DisconnectAll：void。
- 出力には公式SDK、Newtonsoft.Json、両者のライセンス、第三者通知を含む。供給されたSDK配布に別のNOTICEファイルはない。

## 実機なしの自動検証

通常テスト64チェック、UIテスト5チェック。

UI改修後：Releaseビルド成功（警告0・エラー0）、UIテスト7チェック成功。初期折りたたみとクリック展開を追加確認し、WinFormsの描画画像でレイアウトを確認した。ライト基調、右上再接続、下部操作の右寄せ・保存ボタン強調を実装。

- UTF-8、BOM、改行、長さ上限、引数個数、整数範囲、チャンバー重複、強度個数。
- シリアルの完全一致、未接続・未知対象の破棄。
- 指定対象だけの停止→噴射、チャンバーごとの既定強度、今回だけの上書き強度、ブースター値。
- SDK呼び出しを意図的に保留した状態でSTOPを投入し、優先処理と待機中SHOOTの取消を確認。
- 個別STOPが待機中ALLの該当機器だけを除外し、他機器へのSHOOTを維持。
- キュー100件上限、満杯時STOP、再接続中の破棄とキュー取消。
- 1台の停止例外によって別の機器の処理が止まらないこと。停止・切断例外後の終了処理。
- 設定の型・項目・範囲・版・重複プロパティ、保存/再読み込み、破損ファイル保全、外部変更検出。
- 実際のループバックUDPパケットから模擬SDKまでの中継。
- ポート変更、競合時の旧待受維持、同じポートのアドレス変更、旧ソケットを閉じた後の復旧、保存失敗時の待受維持。
- 別プロセスから単一起動イベントを通知し、二重起動側が終了。
- 実際のWinFormsメッセージループで通常起動がトレイのみ、通知で設定画面表示、閉じた後の常駐、トレイメニュー終了で停止・切断・ポート解放・アイコン非表示。

テストでは公式SDKをIDeviceの模擬実装へ差し替える。UI試験はプログラムによる操作であり、DPIや全画面サイズでの目視確認を保証しない。

## 未検証

- USB/BLE実機接続、3000ms噴射と自動停止、途中STOP、複数チャンバー、強度変更、置換噴射。
- 複数実機、抜線、再接続、終了時の実機停止、AromaPlayerとのCOM占有競合。
- SDKの実機接続時の例外条件、最大噴射長、切断検出、呼び出し所要時間。
- 別PCからの通信、ファイアウォール環境ごとの差、Windowsログオフ・強制終了。

SDKの呼び出しが長時間戻らない場合、STOPや終了はその呼び出しの終了を待つ。SDKを強制中断する処理はない。ログのファイル書込は別ワーカーで行い、保留が2000件を超えるとファイル用ログを破棄してUIへ記録するため、ディスク障害が制御を停止させない。
