# AromaShooter UDP Bridge

AromaShooter UDP Bridge は、UDPで受信した噴射・停止指示をAromaShooter公式Windows SDKへ中継するWindowsトレイアプリです。

## Installation

最新の[Release](https://github.com/your-repo/AromaShooter-UDP-Bridge/releases)をダウンロードしてください。

- この配布設定はWindows x64向けです。
- アプリは機器のドライバーをインストールしません。
- SDKのDLLとNuGet依存関係はアプリに含まれます。

## Usage

1. ZIPを展開し、`AromaShooterUdpBridge.exe`を起動します。
2. 初回は設定ファイルが作成され、設定画面が表示されます。タスクトレイからも設定画面を開けます。
3. 接続方式をUSBまたはBLEに設定し、必要に応じてUDP待受IP・ポートを変更して「適用して保存」を押します。
4. アプリケーションの起動後にデバイスを接続した場合は「再接続」を実行し、検出された機器のシリアル番号と状態を確認します。
5. 「テスト」を開き、対象・チャンバー・噴射長を指定して噴射を確認します。
6. 外部ソフトから、このPCのIPアドレスとUDPポートへコマンドを送信します。

「起動時自動接続」が有効な場合は起動時に接続を試みます。設定画面を閉じてもアプリはトレイに常駐します。完全に終了するにはトレイメニューの「終了」を使ってください。二重起動すると、新しいプロセスは終了し既存の設定画面を表示します。

### トレイメニュー

| 項目       | 動作                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| 設定・状態 | 設定画面を開きます。先頭の●はエラーありで赤、エラーなしで接続機器ありなら緑、機器なしならグレーです。 |
| 全停止     | 接続機器を停止し、待機中の該当噴射指示を取り消します。                                                |
| 再接続     | 機器を停止・切断し、現在選択されている方式で再検出します。                                            |
| 終了       | UDP待受を止め、機器を停止・切断して終了します。                                                       |

エラー表示はアプリ起動後に記録されたエラーに基づきます。接続一覧は最後の検出結果であり、機器の状態を常時監視するものではありません。

## 設定

初期値は待受IP `0.0.0.0`、UDPポート`10000`、接続方式USB、自動接続有効です。`0.0.0.0`は全IPv4インターフェースで待ち受けるため、別PCから受信する場合はWindowsファイアウォールの受信規則を確認してください。アプリはファイアウォールを自動変更せず、送信元IPの許可リストも提供しません。同一PC内だけで使う場合は`127.0.0.1`に設定できます。

「詳細設定」ではチャンバー1〜6の既定強度、内部ブースター、外部ブースターを設定します。「テスト」では機器、チャンバー、噴射長を指定できます。UDPの強度省略時はチャンバーごとの既定強度を使用します。内部ブースターは1〜100、外部ブースターとチャンバー強度は0〜100です。設定変更だけでは噴射しません。

設定ファイルは次の場所に保存されます。

```text
%LOCALAPPDATA%\\AromaShooterUdpBridge\\settings.json
```

初期設定の例：

```json
{
  "schemaVersion": 1,
  "udp": {
    "listenAddress": "0.0.0.0",
    "port": 10000
  },
  "device": {
    "transport": "USB",
    "autoConnect": true
  },
  "shoot": {
    "defaultIntensities": [100, 100, 100, 100, 100, 100],
    "internalBoosterIntensity": 100,
    "externalBoosterIntensity": 0
  }
}
```

JSONを外部編集した場合は、設定画面の「設定を再読み込み」を押してください。編集中にファイルが外部変更された場合は、競合を知らせます。既存の設定が壊れている場合は自動で上書きせず、UDP待受と自動接続を開始しません。内容を修正するか、画面から明示的にリセットしてください。設定フォルダーとログは画面左下の「設定フォルダーを開く」から確認できます。

## UDPコマンド

プレーンテキストのUTF-8 UDPです。1データグラムにつき1コマンドを送信します。応答やACKはありません。最大1024バイトで、コマンド間に改行やタブを入れないでください。

### 噴射

```text
SHOOT <対象> <チャンバー> <噴射長ms> [強度]
```

```text
SHOOT ALL 1 3000
SHOOT ALL 1,3 3000
SHOOT ALL 1,3 3000 50,80
SHOOT ASN3A01192 2 1500 70
```

対象は`ALL`または設定画面に表示されたシリアル番号です。チャンバーは1〜6、強度は0〜100です。複数チャンバーを指定する場合、強度も指定するなら個数と並び順を一致させてください。強度を省略すると設定値を使います。噴射長は必須の正整数で、単位はミリ秒です。たとえば`3000`は3秒です。実機で有効な噴射長の上限は確認が必要です。

同一機器への各噴射は、先に全チャンバーとブースターを停止してから実行します。USBでは停止後に100ms待って噴射します。BLEではこの待機を入れません。待機中に対象のSTOPを受けると、その噴射は取り消されます。新しいSHOOTは制御キュー順に処理されます。キューの上限は100件で、上限を超えたSHOOTは破棄されます。

`ALL`は処理時点で接続している機器を対象にします。未接続・未知対象の指示は破棄され、接続後に再生されません。複数機器の処理は直列です。SDK呼び出し完了ログは呼び出しが戻ったことを示すだけで、実機で噴射したことの確認ではありません。

### 停止

```text
STOP ALL
STOP ASN3A01192
```

対象機器の全チャンバーとブースターを停止します。対象の待機中SHOOTも取り消します。特定機器へのSTOPは他機器の噴射を取り消しません。STOPはSDK処理中の呼び出しを中断するものではなく、その呼び出しが戻った後に処理されます。

### PowerShell送信例

同じPCのUDPポート10000へ`SHOOT ALL 1 3000`を送ります。別PCから使う場合は宛先をアプリ実行PCのIPアドレスに変更します。

```powershell
$udpClient = New-Object System.Net.Sockets.UdpClient
try {
    $message = 'SHOOT ALL 1 3000'
    $payload = [System.Text.Encoding]::UTF8.GetBytes($message)
    [void]$udpClient.Send($payload, $payload.Length, '127.0.0.1', 10000)
}
finally {
    $udpClient.Dispose()
}
```

停止する場合は`$message`を`'STOP ALL'`にします。UDPには配送保証がありません。SHOOTを再送すると噴射が再開始する場合があるため、無条件の再送は避けてください。安全のため噴射長を必ず指定してください。

## ログとトラブルシューティング

設定画面にはUDP待受状態、接続方式、検出機器、エラー、直近の受信・実行ログが表示されます。メモリ上のログは直近500件、ファイルログは設定フォルダー内の`logs`に日別で保存され、7日分を保持します。

| 症状                           | 確認すること                                                                                                                |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| UDP待受を開始できない          | 設定画面のエラー、待受IP・ポート、同じポートを使う他アプリを確認します。                                                    |
| 別PCから受信できない           | 宛先IP・ポート、待受IP、Windowsファイアウォールの受信規則を確認します。                                                     |
| 機器が検出されない             | USB/BLEの選択、電源、USBのCOM認識、Bluetooth LEを確認して再接続します。                                                     |
| USBで接続できない              | 同じCOMポートを使うAromaPlayerなどを終了してから再接続します。                                                              |
| コマンドを受信したが噴射しない | ログの拒否理由、対象シリアル、チャンバー・強度、カートリッジを確認します。                                                  |
| 設定を編集しても反映されない   | 「設定を再読み込み」を押し、JSONの構文・項目・値の範囲を確認します。                                                        |
| .NETや依存DLLのエラーが出る    | ZIPに発行フォルダー内のファイル一式が入っているか確認します。通常ビルド出力でなく、自己完結型の発行出力を配布してください。 |

## 開発者向け

Windows上で.NET 10 SDKと.NET Desktop開発環境を用意してください。`global.json`は.NET SDK 10.0.100を指定し、同じ機能バンド内の更新版へロールフォワードします。公式SDK DLLは`lib/net472/AromaShooterWindowsSDK.dll`に置きます。NuGet依存関係はビルド時に復元されます。

公式SDKとサンプル：<https://github.com/aromajoin/aromashooter-sdk-windows>
